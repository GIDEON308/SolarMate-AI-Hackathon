SolarMate AI — App Map

A local, deterministic proof of concept for investigating solar inverter shutdown under load.

This map follows the current application code. It is a local snapshot, not a separate app page, and may drift if the source changes.

One case, from form to guidance

  1. Technician input

    templates/index.html

    Named form fields are sent as a POST to /.

  2. Flask route

    app.py, index()

    Receives the submitted values and connects validation, guidance, and rendering.

  3. Local analysis and guidance

    solarmate/analysis.py, analyze_case()

    solarmate/guidance.py, guidance_for_case()

    Validates inputs, calculates results, and supplies fixed ordered checks and safety notes.

  4. Rendered results

    templates/index.html

    Separates calculations, technician readings, evidence-based findings, troubleshooting checks, and safety.

Guided source route

The guided walkthrough covered these actual source sections in chat. This route is for revisiting the same behavior in an editor; it does not claim that the learner separately navigated each file in the editor.

  1. templates/index.html — find the POST form, then the Calculations, Measurements, Evidence-Based Findings, Troubleshooting Checks, and Safety sections. The first shows result fields computed by Python; the second displays only accepted technician readings.
  2. app.py — find index() to see how submitted values go to analysis.py's analyze_case(), then how successful results are enriched with guidance before rendering.
  3. solarmate/guidance.py — find TROUBLESHOOTING_CHECKS, SAFETY_GUIDANCE, and guidance_for_case(). Their ordered content is rendered by the corresponding lists in index.html.

To change this, start here

  • Form fields or result labels: templates/index.html.
  • Validation, bank calculations, or optional-reading rules: solarmate/analysis.py.
  • Fixed troubleshooting wording or safety notes: solarmate/guidance.py.
  • Rendered behavior regression coverage: tests/test_routes.py.
  • Local setup and demo inputs: README.md.

A practice to reuse

Turn a product requirement into an observable result, then test that result. Here the approved primary-case figures are checked in tests/test_routes.py, and the rendered check list is compared directly with the fixed tuple in guidance.py. On another project, the same approach helps catch mismatches between what was agreed and what users actually see.

Run this project again

From the project folder in Windows PowerShell or Command Prompt:

py -3 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python app.py

Open http://127.0.0.1:5000. Run checks with:

python -m unittest discover -s tests
